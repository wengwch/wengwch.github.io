本周关键词是：agent 能力产品化、编码模型多样化、可观测与安全补课。Claude Sonnet 5、GitHub Copilot、Gemini、Kimi、GLM 与编码 agent 安全研究共同指向一个趋势：开发者工具正在从"模型选择"转向"模型 + 工具 + 权限 + 成本 + 审计"的完整工程系统。

## 本周摘要

1. Claude Sonnet 5 发布并进入 GitHub Copilot，支持 1M 上下文和更强 agentic workflow，但迁移时要注意 tokenizer、thinking 和采样参数变化。

2. Copilot 本周集中补齐 agent 工作流：浏览器工具 GA、JetBrains AI Assistant 集成、agent session streaming 公测、Kimi K2.7 Code 进入模型选择器。

3. Gemini API 推出 Omni Flash 视频生成预览，并让低延迟图像生成模型 GA，AIGC API 的竞争继续从单图生成扩展到多模态编辑链路。

4. 编码 agent 安全风险更清晰：研究和案例都显示，未知仓库、安装脚本、DNS/网络访问和工具执行日志需要进入默认威胁模型。

## 重点动态

### Claude Sonnet 5 进入日常 agent 场景

Anthropic 6 月 30 日发布 Claude Sonnet 5，API 模型名为 `claude-sonnet-5`，支持 1M token 上下文、128k 最大输出，并在 8 月 31 日前提供 introductory pricing。迁移上有三个细节值得开发者直接检查：adaptive thinking 默认开启，手动 extended thinking 参数会返回 400，非默认采样参数也会返回 400；新 tokenizer 对同一文本可能产生更多 token，成本估算需要重算。

GitHub 同日宣布 Sonnet 5 可用于 Copilot，覆盖 VS Code、Visual Studio、Copilot CLI、cloud agent、GitHub Mobile、JetBrains、Xcode 和 Eclipse 等入口。这说明 Sonnet 5 的目标不是单次问答，而是进入 IDE、CLI 和云端 agent 的常态开发链路。

### Copilot 把 agent 变得更可控

GitHub 本周连续更新 Copilot agent 能力。VS Code 浏览器工具在 7 月 1 日 GA，agent 可以打开页面、点击、输入、处理弹窗、读取页面内容、截图并抓取 console 错误；权限设计上，用户标签页默认不共享，agent 自己打开的标签页隔离运行，摄像头、麦克风、位置、通知和剪贴板读取等敏感权限需要显式批准。

7 月 2 日，Copilot agent session streaming 进入公测，企业可以通过 streaming endpoint 或 REST API 获取 prompts、responses 和 tool calls 等 session 数据。这是一个重要信号：agent 生产化不是只看完成率，还要能接入 SIEM、审计、成本中心和合规流程。

### Kimi K2.7 Code 进入 Copilot 模型池

GitHub 7 月 1 日宣布 Kimi K2.7 Code 在 Copilot 中 GA，这是 Copilot model picker 中首个 open-weight selectable model，先面向 Pro、Pro+、Max 逐步推出，后续扩展到 Business、Enterprise 和更多表面。它由 GitHub 托管在 Microsoft Azure，按 provider list pricing 计费，企业管理员需要显式开启策略。

这对开发团队的意义是，coding agent 的模型池正在从少数闭源模型扩展到可替换、多价位、多治理策略的组合。选型时要把安全、数据治理、价格、延迟和 IDE/CLI 覆盖面一起看。

### Gemini API 加速多模态生成

Google Gemini API changelog 显示，6 月 30 日 `gemini-omni-flash-preview` 进入 public preview，面向高速视频生成和对话式视频编辑，可通过 Interactions API 生成 3-10 秒 720p 视频，也支持基于静态图像生成与迭代编辑。同日，`gemini-3.1-flash-lite-image` 正式 GA，定位低延迟、低成本图像生成与编辑。

AIGC 工程上，这类更新会推动应用从"调用一个文生图接口"转向"脚本、素材、图像、视频、对话式编辑、审核和缓存"的组合流水线。短视频、营销素材和产品图自动化会更快进入可批量生产阶段。

### Copilot 与 JetBrains 继续融合

GitHub 和 JetBrains 6 月 30 日宣布，Copilot Agent 可在 JetBrains AI Assistant 中作为一等 agent 入口选择。开发者可以在 AI chat 中选择 GitHub Copilot，切换模型并调整 reasoning depth，让 agent 处理多步编码任务、运行命令并迭代修改。

这类集成会削弱"某个 IDE 自带哪个助手"的边界，agent 更像跨 IDE 的工作流层。团队要关注统一规则文件、权限策略、命令白名单和 PR 审查，而不是只按编辑器拆分治理。

### Z.ai 推出 ZCode，编码 agent 价格战继续

Business Insider 报道，Z.ai 推出 ZCode，定位统一的规划、编码、评审和部署工具，并支持包括 GLM-5.2 在内的模型。报道提到其订阅价格低于 Cursor、GitHub Copilot 等主流工具，引发围绕功能相似性、开源生态和全球 AI coding 竞争的讨论。

这说明 coding agent 的竞争已经进入产品形态和价格层面。对个人开发者是更多选择；对企业则意味着需要更严格的工具准入、代码外发策略和供应商评估。

## 研究与趋势

一篇针对 1.8 亿开源仓库的研究尝试识别 AI coding agents 的真实使用痕迹。论文指出，单靠 bot 账号会严重低估采用率；多方法检测发现 Claude Code 在样本中有大量 commit 级痕迹，而 PR 级统计与 commit 级统计覆盖的人群几乎不同。这提醒我们：AI 写代码正在以更隐蔽的方式进入供应链，仓库治理不能只盯 PR 作者名。

安全侧，本周 Mozilla 0din 团队相关案例显示，编码 agent 可能被一个看似干净的仓库诱导执行恶意初始化流程，通过脚本和 DNS TXT 间接拉起 reverse shell。这个案例的关键不是某个工具是否中招，而是 agent 的"乐于修复环境"会放大未知安装脚本、网络访问和 shell 执行的风险。

工具调用研究也在收敛到同一方向：单次 function calling 已经不够，真实 agent 需要多工具编排、长轨迹状态、执行反馈、安全约束和成本约束。MCP、浏览器工具、Computer Use、IDE agent 和 cloud agent 都在把这个问题推向工程实践。

## 开发者行动建议

1. 为 coding agent 设置最小权限：未知仓库默认禁用自动安装、外网访问和 shell 执行；需要执行时保留命令日志和人工确认。

2. 重新测算 Sonnet 5、Kimi K2.7 Code、Gemini 视觉模型等新模型的 token、价格、延迟和失败率，不要沿用旧模型预算。

3. 给 agent session 建立审计字段：模型名、prompt、工具调用、文件变更、命令、网络访问、审批人和最终 PR。

4. 把浏览器工具、MCP server、Computer Use 和 CLI agent 分成只读、可写、可联网、有副作用四类权限，默认从只读开始。

5. 对开源模型进入企业 coding workflow 做单独评审：关注许可证、托管位置、数据保留、模型路由、管理员策略和禁用开关。

## 本周判断

AI coding 的下一轮竞争不只是"谁的模型更会写代码"，而是谁能把 agent 放进真实开发系统后仍然可控。模型池会越来越多，IDE 入口会越来越碎，真正稀缺的是统一规则、可观测性、权限边界和失败恢复。短期内，能把这些基础设施补齐的团队，才更容易把 AI coding 从个人提效变成团队级生产力。
