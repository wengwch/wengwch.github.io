本周关键词是：agent 基础设施升级。模型继续变快、变便宜，但更值得关注的是异步 coding agent、MCP 无状态化、用量治理、沙箱逃逸和生产评估正在一起塑造开发者平台的新基线。

<!-- more -->

## 本周摘要

1. GitHub Copilot 在一周内补齐 Linear 异步任务、移动端修复 Actions、MCP 新规范适配、用量影响看板和仓库级指标，coding agent 正在进入项目管理与度量闭环。

2. Gemini 3.6 Flash 和 3.5 Flash-Lite GA，主打更低成本、更适合代码与 agent planning；GitHub Copilot 随后接入 Gemini 3.6 Flash。

3. OpenAI 发布 Presence，把 agent 从模型 API 推向可部署、可评估、可审批、可持续改进的企业工作流产品，并由 Codex 辅助分析生产信号。

4. Claude Code 本周更新 Opus 5、1M context、严格网络 allowlist、嵌套 subagent、后台 code review 和更细的沙箱/信任修复，长任务工程化继续加速。

5. MCP 2026-07-28 规范临近正式发布，TypeScript、Python、Go SDK 都在适配无状态核心、请求级元数据、缓存提示和追踪；安全研究则继续提示 MCP/tool layer 是 agent 的主战场。

## 重点动态

### Copilot 把 agent 接进真实协作流

GitHub 7 月 23 日宣布 Copilot cloud agent for Linear GA。把 Linear issue 分配给 Copilot 后，后台 agent 会分析需求、实现变更并产出 PR，这让 coding agent 从 IDE/CLI 入口进一步进入任务系统。

同日，GitHub Mobile 支持在 Actions check 失败时直接让 Copilot cloud agent 调查并修复；GitHub Issues 也开放 agent automation controls 公测，用来解释、审核 agent 对 issue 的标记、归类、分配和关闭动作。7 月 22 日的 Copilot usage metrics impact dashboard，以及 7 月 17 日已 GA 的仓库级 Copilot metrics API，则把 adoption、PR 活动、code review 与 coding agent 产出带进管理面板。

这组更新的意义不在单个按钮，而在流程闭环：需求来自项目管理，修复发生在 PR/Actions，管理者可以看用量和效果，团队开始需要定义哪些任务允许 agent 自主处理、哪些必须人工确认。

### Gemini Flash 系列进入成本敏感的 agent 位

Google 7 月 21 日在 Gemini API release notes 中发布 Gemini 3.6 Flash 与 Gemini 3.5 Flash-Lite GA。前者强调 token 效率、代码和 agentic planning，后者面向低延迟、高吞吐自动化场景。GitHub Copilot 同日宣布 Gemini 3.6 Flash 开始滚动接入，定位也是 web/app 开发、coding 与较长周期 agentic tasks。

一个容易被忽略的变更是 Gemini API 对 `temperature`、`top_p`、`top_k` 等采样参数做了弃用说明。对开发者来说，这意味着新模型接入不能只替换 model id；需要重新检查生成稳定性、回归测试、提示词和工具调用策略，尤其是依赖采样参数控制输出风格的 SDK 封装。

### Presence 显示 agent 产品化方向

OpenAI 7 月 22 日发布 Presence，定位为面向高规模、高风险工作流的托管 agent 产品。它不是自助模型端点，而是由 FDE 和系统集成伙伴交付，用于客服、理赔、IT 服务、销售与内部流程等场景。

Presence 的技术信号值得开发者关注：上线前用模拟与 grader 检查是否遵守政策、是否正确用工具、是否应该升级给人工；上线后收集生产会话、升级事件和质量信号，再由 Codex 结合 Presence plugin 调查问题并提出改动，最后由团队测试并批准灰度。agent 平台的竞争点正在从"回答得好"扩展到"能否被评估、上线、监控、修订和回滚"。

### Claude Code 强化长任务执行边界

Claude Code 7 月 24 日更新加入 Claude Opus 5，并把它作为默认 Opus 模型，支持 1M context 与 fast mode；同时新增 `sandbox.network.strictAllowlist`，可让沙箱命令只访问 allowlist 主机。更新还加入 `DirectoryAdded` hook、headless init 事件中的 MCP server config validation 错误、嵌套 subagent 转发，以及动态 workflow 规模指南。

7 月 22 日版本把 `/code-review` 改为后台 subagent，修复多个远程控制、MCP 认证、上下文溢出和 sandbox/IDE 交互问题，并要求不可信目录中的 agent frontmatter hooks 先通过 workspace trust。整体方向很清楚：coding agent 会越来越长时间运行、跨目录、跨工具、跨 subagent，因此网络出口、目录信任、hook 执行和后台任务可见性都必须成为一等配置。

### MCP 无状态化进入倒计时

MCP 2026-07-28 release candidate 已锁定，最终规范计划在 7 月 28 日发布。核心变化是移除协议级 session 和 `Mcp-Session-Id`，每个请求携带协议版本、client 信息和能力元数据；`server/discover` 替代初始化握手；`Mcp-Method`、`Mcp-Name`、缓存提示和 trace context 让网关、缓存和可观测性更容易落地。

GitHub MCP Server 已提前支持下一版规范；MCP TypeScript SDK、Python SDK 和 Go SDK 也在推进 2026-07-28 支持。对现有 MCP server 维护者，接下来两周最重要的是检查：是否把状态藏在 session 里、是否依赖旧 Tasks/Roots/Sampling/Logging 行为、是否需要支持新 header、缓存语义和 requestState。

## 研究与趋势

ACL Industry Track 的 ShieldMCP 论文把 MCP 风险总结为工具层威胁：tool poisoning、间接 prompt injection、供应链操控不是传统模型安全能单独解决的问题。论文提出运行时拦截架构，对 tool call 和 response 做结构与语义校验；在红队评估中显著降低攻击成功率，同时增加较低延迟。

另一条安全线来自本周媒体对 Pillar 研究的报道：多个 AI coding agent 曾被证明可通过仓库内容诱导配置改写，再借 IDE 扩展、Git 集成或宿主组件越过沙箱执行命令。无论具体 CVE 归属如何，结论都很现实：agent 不只是"在沙箱里运行命令"，它还能改写未来会被宿主读取的文件，安全边界必须覆盖宿主、插件、配置和后续自动化。

AgentLens 则从评估角度补上另一块拼图。它不只看任务是否通过，而是评估 agent 的完整轨迹：是否遵守指令、如何用工具、是否验证、如何恢复错误、如何与用户沟通。随着 agent 进入生产，轨迹评审会比单一 benchmark 更接近真实质量。

## 开发者行动建议

1. 若维护 MCP server，尽快做 2026-07-28 兼容性清单：session 状态、discover、headers、缓存、trace、Tasks 迁移和弃用能力都要逐项验证。

2. 给 coding agent 增加网络 allowlist 和敏感文件演练，尤其检查 `.env`、历史凭据、私有依赖、IDE 配置、hook 和自动化脚本。

3. 把 agent 产出的 PR 纳入度量：来源 issue、模型、工具调用、CI 修复次数、人工 review 发现、回滚率和用量成本都应可追踪。

4. 接入 Gemini 3.6 Flash、Opus 5 或其他新模型时，不要只替换模型名；同步回归提示词、采样参数、工具调用、成本和延迟。

5. 对长任务 agent 建立"轨迹评审"：不只看最终 diff，也要看它是否误读需求、跳过验证、扩大权限或在错误路径上持续执行。

## 本周判断

AI 开发工具正在从模型驱动转向系统驱动。模型变强仍然重要，但本周更关键的变化是：agent 进入任务系统、移动端、企业部署、MCP 网关、度量面板和安全运行时。

下一阶段的开发者平台竞争，不会只比谁的模型更会写代码，而会比谁能把 agent 放进可审计、可扩展、可回滚的生产路径。对团队来说，最该提前建设的是三件事：工具边界、执行轨迹和成本度量。
