本周关键词是：工程控制面。模型继续降价、提速并扩展到机器人，但更值得开发者关注的是，agent 的配置、权限、成本、可观测性和供应链防护正在快速变成标准能力。

<!-- more -->

## 本周摘要

1. OpenAI 下调 GPT-5.6 Luna 与 Terra 价格，推出更快的 API Fast mode，并发布官方 Terraform provider，模型平台开始像云资源一样进入基础设施即代码。

2. GitHub 把统一托管设置扩展到 Copilot app 与 cloud agent，同时在 JetBrains 补上 OpenTelemetry、token 上限、MCP 和自定义 agent 管理。

3. MCP 2026-07-28 正式规范落地：无状态核心、Extensions、Tasks、MCP Apps、OAuth/OIDC 加固与完整 JSON Schema 共同构成新基线。

4. Gemini Robotics ER 2 把多步工具编排、代码执行、流式音视频和函数调用带入具身 agent；腾讯云 TokenHub 则新增 MiMo-V2.5-Pro，统一模型入口继续扩容。

5. GitHub 开始拦截疑似恶意 Actions 工作流，并扩大恶意依赖告警覆盖；agent 时代的安全边界正从生成代码延伸到 issue、依赖与 CI 执行链。

## 重点动态

### 模型 API 同时争夺价格、速度与运维入口

OpenAI 7 月 30 日宣布 GPT-5.6 Luna 降价 80%、Terra 降价 20%，并以 Fast mode 替代 Priority Processing。GPT-5.6 Sol 的 Fast mode 可提供最高约 2.5 倍速度，价格为标准处理的两倍，原有 priority 请求会自动兼容迁移。

更有长期意义的是 7 月 29 日发布的官方 Terraform provider。团队现在可以用同一套 IaC 流程管理项目、用户、角色、服务账号、证书与项目级 rate limit，审查配置变更并检测漂移。模型调用不再只是 SDK 里的一个 API key，而是正式进入平台工程与权限治理体系。

7 月 28 日上线的 GPT Transcribe 与 GPT Live Transcribe，则分别面向文件转写和 Realtime 低延迟流式转写，支持自由文本上下文、关键词提示与多种预期输入语言。语音 agent 的模型入口进一步标准化。

### Copilot 把 agent 治理延伸到更多执行端

GitHub 7 月 27 日把 enterprise managed settings 扩展到 Copilot app 和 cloud agent。企业可用统一的 `managed-settings.json` 控制插件、插件市场、是否允许跳过命令/文件/URL 审批，以及默认模型策略；托管值优先于开发者本地设置。

同日的 JetBrains 更新支持为 agent workflow 导出 OpenTelemetry，给 BYOK 和自定义端点设置 `maxInputToken`、`maxOutputToken`，并在 Claude agent flow 中直接使用 MCP server 与自定义 agent。配置、成本和轨迹开始跨 IDE、桌面端、CLI 与云端任务统一起来。

这意味着团队的 agent policy 不应再绑定某个编辑器。更合理的做法是把允许的工具、模型、市场、审批绕过规则和遥测出口定义成组织级策略，并验证每个执行端是否真正继承。

### MCP 2026-07-28 成为新的兼容目标

本周正式发布的 MCP 2026-07-28 移除 `initialize` 握手与协议级 session，以 `server/discover` 和请求级 `_meta` 取代；`Mcp-Method`、`Mcp-Name`、缓存提示与 W3C Trace Context 让请求更容易被网关路由、缓存和追踪。

Extensions 成为一等机制，MCP Apps 和长任务 Tasks 以扩展方式独立演进；工具 schema 升级到完整 JSON Schema 2020-12。授权部分强化 `iss` 校验、凭据与 issuer 绑定、scope step-up 等规则，Roots、Sampling、Logging 则进入弃用周期。

对 server 维护者，迁移重点不是简单修改版本号，而是把隐藏在 session 中的业务状态改为显式 handle，检查 Tasks 生命周期、错误码、schema 验证上限、OAuth issuer 和 trace 传播。TypeScript SDK 指南也明确提示，新协议需要显式 opt-in，不能假设升级依赖后会自动切换 wire format。

### 多模型平台继续扩容，agent 开始连接物理世界

腾讯云 TokenHub 7 月 27 日新增 MiMo-V2.5-Pro，此前已接入 Kimi K3、GLM、DeepSeek、Qwen 等模型。统一入口的价值不只是模型数量，而是让团队集中处理 key、配额、账单和模型切换；代价则是需要验证兼容层是否完整保留 reasoning、tool call、缓存和流式事件语义。

Google 7 月 30 日发布 Gemini Robotics ER 2 预览端点，支持空间推理、agentic code execution、多步工具编排、多机器人协同，以及通过 Live API 进行双向音视频流。函数调用还提供面向物理动作的阻塞行为。工具调用正在从无副作用查询走向真实世界动作，审批、超时、幂等和紧急停止会比提示词更重要。

### agent 供应链防护前移

GitHub 7 月 28 日开始对公共仓库中疑似恶意的 Actions workflow 自动暂停执行，必须由有写权限的协作者在认证网页会话中批准。同时，Dependabot 接入 OpenSSF malicious-packages 数据，扩大 npm、PyPI 等生态的恶意包告警。

coding agent 可以根据 issue 修改 workflow、更新依赖并触发 CI，因此仓库内容本身已成为输入通道。团队需要把外部 issue、PR、附件和依赖元数据都视为不可信输入，而不能只审查 agent 最终生成的源码。

## 研究与趋势

IssueTrojanBench 用恶意 issue、评论和 PDF 等六类投递路径测试 Cursor、Claude Code 与 Codex Desktop。论文报告 66.5% 的恶意任务穿透模型与 agent 两层防线，并指出拒绝主要来自底层模型，agent harness 提供的额外保护有限。虽然具体结果会随版本变化，但它清楚说明：issue 到执行环境之间需要独立的输入扫描、权限隔离和动作审批。

ICAE-Bench 则把评估从“完成明确 bug fix”推进到“根据模糊产品需求互动建项目”。它用自动 User Agent 逐步揭示约束，再从功能、API、结构、设计和互动质量多维评分。未来 coding agent benchmark 会更接近真实产品协作，而不是只看静态测试是否通过。

另一项 MCP 网关研究表明，通过工具检索、协议适配、访问控制和会话路由，可把 agent 可用工具扩展到 3,000 个以上；其报告的混合检索达到 98% Top-15 recall，并显著减少工具选择时间与 token。信号很明确：工具数量增长后，检索与网关会成为 agent 基础设施的核心层。

## 开发者行动建议

1. 为模型平台建立成本回归表：标准、Fast、批处理和不同模型档位都记录质量、p95 延迟、单任务 token 与总成本，避免只看单价。

2. 若使用多个 coding agent 入口，把插件市场、MCP allowlist、审批绕过、token 上限和 OTel 出口整理为统一策略，并逐端验证。

3. 启动 MCP 2026-07-28 兼容测试，重点覆盖无状态请求、显式业务 handle、Tasks、OAuth issuer、缓存、trace 和复杂 JSON Schema。

4. 对 issue 驱动的自动化增加信任分级：外部附件、评论、workflow 与依赖更新默认进入低权限沙箱，敏感动作必须人工批准。

5. 使用聚合模型 API 时做协议保真测试，尤其检查 reasoning 字段、并行 tool call、流式事件、错误码、缓存命中和限流语义。

## 本周判断

agent 平台的竞争正在从“谁能完成任务”转向“谁能被稳定管理”。降价和更强模型会扩大使用量，但真正决定能否进入生产的是统一配置、可观测性、预算边界、协议兼容和供应链防护。

本周最值得提前投入的不是再增加一个 agent，而是建立一个跨模型、跨客户端、跨工具的控制面。谁先把身份、权限、成本和轨迹打通，谁才更可能安全地扩大自动化范围。
