本周关键词是：可移植、可调度、可审计。模型能力仍在上升，但更重要的变化发生在模型外围：agent 插件开始跨客户端复用，推理速度与思考强度成为独立档位，长任务也被纳入成本和合规控制。

<!-- more -->

## 本周摘要

1. DeepSeek V4 Pro 正式版上线，原生支持 OpenAI Responses API，并针对 Codex 做适配；模型新增三档思考强度，同时宣布分时 API 定价。

2. Agent Plugins 1.0 在 VS Code、Copilot CLI、Copilot SDK 与 Copilot app 全面可用，将 Skills 与 MCP server 打包为可跨 agent 客户端安装的统一插件。

3. OpenAI 为 GPT-5.6 Sol 公布最高可达标准档 14 倍速度的 Ultrafast mode，首批仅向部分客户开放预览。

4. Claude Platform 把本地 Claude Code 与 Cowork 会话纳入 Compliance API，并通过响应头返回实际命中的 workspace，企业审计进一步覆盖开发者终端。

5. 最新研究认为，多 agent 框架普遍具备基础编排能力，但遥测等高级工程能力仍不完整；GUI agent 同样缺少恢复、升级、审计与生命周期测试。

## 重点动态

### DeepSeek V4 Pro 从模型升级到 agent 运行时适配

DeepSeek 8 月 13 日发布 V4 Pro 正式版，App、Web 与 API 同步更新，调用仍使用 `deepseek-v4-pro`。新版本重点增强生产环境中的 agent 能力，并原生支持 OpenAI Responses API，官方提供面向 Codex 的配置方式。V4 Pro 与 V4 Flash 还增加 `low`、`high`、`max` 三档思考强度，开发者可以按任务复杂度控制推理投入。

8 月 16 日起，DeepSeek API 将改为峰谷定价：非高峰价格为高峰的一半。对批处理、代码索引和异步 agent，执行时间由纯调度参数变成直接影响成本的变量；现有成本模型应同时考虑缓存命中、模型、思考强度和运行时段。

### Agent Plugins 1.0 统一 Skills 与 MCP 的分发层

GitHub 宣布 Agent Plugins 1.0 在主要 Copilot 客户端 GA。该开放规范由 AWS、Anysphere、Microsoft、OpenAI、Vercel 等共同维护，Google随后加入；一个插件可同时携带 Skills 与 MCP 配置，并用命名空间保留特定客户端的 agents、commands、rules 和 hooks。

这减少了同一能力在多个 coding agent 中重复维护清单和目录结构的成本。企业侧则可通过已启用插件、受信 marketplace 与 MCP allowlist 共同治理分发。插件因此不只是提示词包，而是包含知识、工具入口和执行规则的软件供应链单元。

### 延迟成为独立产品档，任务编排需要成本感知

OpenAI 8 月 13 日公布 GPT-5.6 Sol 的 Ultrafast mode，宣称速度最高可达 Standard 的 14 倍，目前为限量预览。它与此前 Fast mode 的演进共同说明：模型、推理强度和服务档位正逐步解耦。

对 coding agent 而言，最合理的默认策略通常不是全程使用最快档，而是让交互式规划、人工等待点和故障恢复优先低延迟，把仓库扫描、批量生成与后台验证留给标准或低价时段。性能评估也应从单一 tokens/s 转向端到端完成时间与每个成功任务的成本。

### 本地 agent 进入统一审计范围

Claude Platform 8 月 11 日扩展 Compliance API，可列出并读取员工机器上运行的 Claude Code 与 Cowork 会话记录；API 响应还新增 `anthropic-workspace-id`，帮助确认请求最终归属的 workspace。与此同时，Claude Sonnet 5 的 $2 / $10 每百万 token 输入/输出价格被确认为长期标准价。

GitHub Copilot 也在 JetBrains 中加入跨会话 memory、本地 Ollama BYOK，以及针对插件、MCP、权限绕过和 OpenTelemetry 的企业设置。终端 agent、云端 agent 与本地模型正在共享同一套记忆、审计和策略问题，团队需要明确哪些上下文可持久化、谁能读取轨迹，以及本地推理是否仍受统一工具权限约束。

### coding agent 从单轮助手变成可操控任务系统

Copilot CLI 新增 `/tasks` 管理 subagent、运行中排队提示与命令、无头模式下先规划再自动实现，以及不依赖 Git 且保留用户编辑的 `/rewind`。这些能力的共同方向不是继续增加聊天入口，而是为长任务补齐排队、回滚、并行状态和人工介入点。

Gemini 3.7 Flash 同期进入 Copilot 的 IDE、CLI 与 cloud agent 等入口，GitHub 强调其在代码库检索、复杂任务验证和最终输出质量上的提升。模型切换越来越容易后，团队应把评估单位从“模型名称”提升为“模型 + agent harness + 权限 + effort + 工具集”的完整配置。

## 研究与趋势

一项针对软件工程多 agent 系统的实证研究比较了主流开源框架，发现它们普遍覆盖基础编排组件，但 agent 遥测等高级能力仍缺失；在共同的 README 摘要任务上，不同框架的 ROUGE 结果也没有显著差异。框架选型应更关注可观测性、故障隔离与运维成本，而非只看是否支持多 agent。

另一篇综述分析了 336 篇 GUI agent 论文。研究指出，感知—推理—行动架构快速成熟，但恢复、人类升级、安全执行、审计和发布后维护仍明显不足；评测也过度集中于任务成功率，且不同协议之间难以直接比较。GUI agent 正变成闭环软件系统，其测试对象应包含完整执行轨迹与异常恢复，而不只是最终截图或成功标签。

两项研究共同指向同一缺口：agent 的“能完成”正在领先于“可运维”。随着插件与多 agent 分发规模扩大，遥测、权限、回滚和可复现评测会成为生产准入条件。

## 开发者行动建议

1. 为模型调用增加 `service_tier`、`effort`、缓存命中和运行时段维度，按成功任务而非单次请求计算成本。

2. 试用 DeepSeek Responses API 时，回归验证多轮 tool call、流式事件、reasoning 状态和 Codex 权限行为，不要只测试文本输出。

3. 把 agent 插件视为依赖包管理：固定来源与版本，审查 Skills、MCP、hooks 和命名空间内容，并限制可用 marketplace。

4. 对持久 memory 与本地会话轨迹制定保留、访问和删除规则；确认本地模型不会绕过统一 MCP allowlist 与审批策略。

5. 为长任务记录计划、工具调用、subagent 状态、人工介入、回滚点和最终验证结果，优先补齐失败诊断能力。

## 本周判断

agent 生态正在形成新的可移植软件层：模型可以替换，Skills 与 MCP 可以打包，插件可以跨客户端分发。接下来的竞争重点将从“谁接入更多模型”转向“谁能安全地复用、治理和观测这些能力”。

同时，速度、思考强度和时段价格的拆分，让 agent 调度开始接近传统计算资源调度。优秀的执行框架不仅要选对模型，还要在每个阶段选对延迟档、推理预算与运行窗口，并为失败保留可审计的恢复路径。
