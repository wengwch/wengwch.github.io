## 本周摘要

本期覆盖 9 月 6 日至 12 日，信息截至北京时间 9 月 12 日晚，约 3 分钟读完。

- Agents API 将会话恢复与工具编排托管化，MCP 也开始直接进入 API 网关。
- DeepSeek V4.1 Flash 上线，旧模型别名的实际指向发生变化；V4 Pro 则继续提供服务。
- 图像生成继续细分速度与编辑精度，coding agent 研究更关注权限和评测是否可信。

## 重点动态

### Agents API：托管的不只是模型调用

OpenAI 9 月 10 日将 **Agents API** 推入公开测试，托管 Codex 运行框架，处理会话编排、上下文压缩和恢复。开发者可接入自定义工具与 MCP，使用持久会话继续任务，并选择托管或自有沙箱。[API 更新](https://developers.openai.com/api/docs/changelog)

对长期运行的开发助手，值得评估的是它能减少多少状态管理代码，以及任务中断后能否可靠续接；执行环境、工具权限和业务验收仍需自行设计。

### DeepSeek V4.1 Flash：关注别名背后的实际模型

DeepSeek 9 月 10 日发布具备原生视觉理解的 **V4.1 Flash**，通过 `deepseek-flash` 调用。旧 V4 Flash 与 V4 Flash Vision Exp 已下线，对应旧模型名暂时路由到新版，API 价格同步下调。[官方更新日志](https://api-docs.deepseek.com/zh-cn/updates/)

截至本期核实，官方已明确 **V4 Pro 在 9 月 14 日后继续提供 API 服务，计费不变**。不要依据早期下线消息仓促迁移；但使用 Flash 旧别名的应用应重新检查视觉输入、工具调用和输出稳定性，因为请求名称没改，底层模型已经变化。

### API Gateway：现有 REST 接口可转为 MCP 工具

Google Cloud 9 月 11 日推出公开预览：通过 OpenAPI 3.x 文档中的 Google 扩展注解，将 API Gateway 配置为远程 MCP 服务，无须修改后端服务即可把 REST API 暴露给 agent。[发布记录](https://docs.cloud.google.com/api-gateway/docs/release-notes)

这降低了存量系统接入 agent 的改造量。落地时应先选择少量语义清晰的接口，明确参数、错误和调用身份，再开放会产生业务变更的操作。

### 图像 API：速度与精细编辑分成两条路线

OpenAI 9 月 8 日发布 **GPT Image 2.5 Sunburst / Flare**，均可通过 Image API 和 Responses 图像工具调用；官方分别将其定位于精细编辑与快速日常生成。[API 更新](https://developers.openai.com/api/docs/changelog)

制作网页素材或营销图时，可以按“初稿生成—局部修改”分别评估模型，记录可用成图率与修改次数，避免仅凭单张生成速度选型。

## 研究与趋势

- **权限应由工具执行层落实。** 9 月 8 日的 CapScope 预印本将每个 agent 的能力权限存放在模型上下文之外，逐次检查工具调用。在其小规模修复实验中，注入效果成功执行从基线的 33–47/75 次降至 3/75 次，修复完成数为 68/75。结果支持权限隔离方向，但仅覆盖五个 Python 任务，不能视为通用防护保证。[论文](https://arxiv.org/abs/2609.08371)
- **榜单分数也需要审计。** 同日发布的 SWE-Bench Pro Verified 针对答案泄漏、隐藏评测信息和任务质量问题修订基准；作者发现部分模型成绩明显回落。选 coding agent 时，应确认基准版本与运行条件，再用自己的仓库任务复核。[论文](https://arxiv.org/abs/2609.08149)

## 开发者行动建议

1. **盘点模型别名**：记录请求名称、实际版本和迁移公告，优先复核 DeepSeek Flash 的现有调用。
2. **试跑一个可恢复任务**：用托管 agent 完成真实但范围有限的工作，观察中断续接、工具失败与人工接管。
3. **把权限落实到执行层**：MCP 先接只读接口；子 agent 按任务授权，避免自动继承全部凭证与工具权限。
4. **建立小型验收集**：代码任务看真实修复与返工，图像任务看成图可用率；同时记录时间和费用。

## 本周判断

本周动态显示，agent 的运行框架正成为可直接购买的平台能力。本文的判断是：接下来团队的差异会更多体现在工具设计、权限边界和验收质量上。选型时，优先比较一次任务从开始到被接受的完整成本。
